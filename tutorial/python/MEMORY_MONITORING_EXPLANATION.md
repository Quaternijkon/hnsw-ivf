# 内存监测方法对比说明

## 问题背景

在使用 `t-hnsw.py` (Python) 和 `benchmark_hnsw.cpp` (C++) 脚本测试相同参数配置时，发现内存占用报告存在显著差异：
- **Python脚本**: 1385.49 MB（整个程序生命周期峰值）
- **C++脚本**: 796 MB（仅搜索阶段峰值）

## 原因分析

### Python脚本的原始监测方式
- **方法**: 使用 `resource.getrusage().ru_maxrss`
- **监测范围**: **整个程序生命周期的峰值内存**（从程序启动到结束）
- **包含内容**:
  - Python解释器初始化
  - 数据加载阶段（基础集、查询集）
  - 索引构建/加载阶段
  - 搜索阶段
  - Python对象开销

### C++脚本的监测方式
- **方法**: 使用 `/proc/self/status` 读取 `VmRSS`
- **监测范围**: **仅搜索阶段的峰值内存**（从搜索开始到搜索结束）
- **包含内容**:
  - 仅搜索阶段的内存使用
  - 不包括数据加载和索引构建阶段

## 解决方案

### 修改后的Python脚本现在提供两种内存指标：

1. **搜索阶段峰值内存 (VmRSS, 与C++对齐)**
   - 使用方法: `PeakMemoryMonitor` 类，在搜索阶段开始监控
   - 监测方式: 读取 `/proc/self/status` 中的 `VmRSS`，与C++脚本完全一致
   - **关键对齐措施**:
     - ✅ 在索引构建/加载完成后释放基础数据集（~512MB）
     - ✅ 在搜索监控开始前释放查询数据集，监控开始后再加载（与C++一致）
     - ✅ 监控时机与C++脚本完全对齐：监控开始时只包含索引，查询数据在监控期间加载
   - **用途**: 与C++脚本进行公平对比

2. **整个程序生命周期峰值内存 (ru_maxrss)**
   - 使用方法: `resource.getrusage().ru_maxrss`
   - 监测范围: 从程序启动到结束的所有阶段
   - **用途**: 了解程序整体的内存占用情况

### 内存对齐的关键改进

为了与C++脚本进行公平对比，Python脚本现在：

1. **释放基础数据集** (Phase 2完成后)
   - C++脚本中，基础数据集在build函数结束后自动释放（局部变量）
   - Python脚本现在也在索引构建/加载完成后显式释放
   - 节省约 ~512MB 内存

2. **重新组织查询数据加载** (Phase 3搜索阶段)
   - C++脚本在搜索监控开始后才加载查询数据
   - Python脚本现在也遵循相同的模式：
     - 在监控开始前释放查询数据
     - 在监控开始后再加载查询数据
   - 确保查询数据的加载也被计入搜索阶段内存

3. **强制垃圾回收**
   - 使用 `gc.collect()` 确保内存立即释放
   - 避免Python的延迟释放导致的内存测量偏差

## 如何正确比较

### ✅ 正确的比较方式
- **Python的"搜索阶段峰值内存 (VmRSS)"** vs **C++的"搜索阶段峰值内存"**
- 这两个指标使用相同的方法（读取 `VmRSS`），监测相同的阶段（搜索阶段），可以公平对比

### ❌ 错误的比较方式
- **Python的"整个程序生命周期峰值内存"** vs **C++的"搜索阶段峰值内存"**
- 这两个指标监测的范围不同，无法直接比较

## 技术细节

### VmRSS vs ru_maxrss

- **VmRSS (Virtual Memory Resident Set Size)**
  - 当前实际占用的物理内存
  - 可以通过 `/proc/self/status` 实时读取
  - 单位: kB（需要除以1024得到MB）

- **ru_maxrss**
  - 进程生命周期内的峰值RSS
  - 通过 `getrusage()` 系统调用获取
  - 在Linux上单位是kB（需要乘以1024转换为字节）

### 为什么会有差异？

1. **监测范围不同**
   - Python: 整个生命周期
   - C++: 仅搜索阶段

2. **Python额外开销**
   - Python解释器本身的内存占用
   - NumPy数组的Python包装器开销
   - Python对象管理开销（引用计数、GC等）

3. **数据加载时机**
   - Python脚本在搜索前已经加载了所有数据
   - C++脚本可能在不同阶段释放/重用内存

## 建议

1. **用于性能对比**: 使用"搜索阶段峰值内存 (VmRSS)"指标
2. **用于资源规划**: 使用"整个程序生命周期峰值内存 (ru_maxrss)"指标
3. **理解差异原因**: 
   - Python脚本的额外内存主要用于Python解释器和数据持久化
   - 搜索阶段的实际内存使用应该与C++脚本相近
