# 动态聚类维护功能实现说明

## 概述

在 `IndexIVF.cpp`、`IndexIVF.h` 和 `IndexIVFFlat.cpp` 中添加了动态聚类维护功能，支持在索引发生较大改动时自动重新计算质心、分裂大聚类和合并小聚类。

## 新增接口

### 1. `recompute_centroids(bool update_quantizer = true)`

重新计算所有聚类的质心。

**功能**：
- 遍历所有倒排列表
- 从每个列表中的向量重新计算质心（平均值）
- 可选择是否更新quantizer

**参数**：
- `update_quantizer`: 如果为true，更新quantizer中的质心

**返回**：重新计算的质心数量

### 2. `split_large_clusters(size_t size_threshold, int split_factor = 2, size_t min_split_size = 100)`

分裂过大的聚类。

**功能**：
- 找出大小超过阈值的聚类
- 使用k-means将大聚类分裂成多个子聚类
- 扩展invlists以容纳新的聚类
- 将新质心添加到quantizer
- 重新分配向量到新的聚类

**参数**：
- `size_threshold`: 触发分裂的聚类大小阈值
- `split_factor`: 每个聚类分裂成多少个子聚类（默认2）
- `min_split_size`: 分裂所需的最小聚类大小（默认100）

**返回**：分裂的聚类数量

**注意事项**：
- 需要 `direct_map.type == Hashtable` 或 `NoMap`
- 会动态扩展 `nlist` 和 `invlists`

### 3. `merge_small_clusters(size_t size_threshold, size_t min_merge_size = 1)`

合并过小的聚类。

**功能**：
- 找出大小小于阈值的聚类
- 找到最近的聚类
- 将小聚类的向量合并到最近的聚类中

**参数**：
- `size_threshold`: 触发合并的聚类大小阈值
- `min_merge_size`: 合并所需的最小聚类大小（默认1）

**返回**：合并的聚类数量

**注意事项**：
- 需要 `direct_map.type == Hashtable` 或 `NoMap`
- 合并后小聚类的列表会变空，但不会删除

### 4. `maintain_clusters(size_t split_threshold, size_t merge_threshold, int split_factor = 2, bool update_quantizer = true)`

综合聚类维护函数。

**功能**：
- 依次执行：重新计算质心、分裂大聚类、合并小聚类
- 返回统计信息

**参数**：
- `split_threshold`: 分裂阈值
- `merge_threshold`: 合并阈值
- `split_factor`: 分裂因子
- `update_quantizer`: 是否更新quantizer

**返回**：`ClusterMaintenanceStats` 结构体，包含：
- `centroids_recomputed`: 重新计算的质心数量
- `clusters_split`: 分裂的聚类数量
- `clusters_merged`: 合并的聚类数量
- `new_nlist`: 新的聚类数量

## 实现细节

### 重新计算质心

```cpp
size_t IndexIVF::recompute_centroids(bool update_quantizer) {
    // 1. 遍历所有倒排列表
    // 2. 从每个列表重建向量
    // 3. 计算平均值作为新质心
    // 4. 更新quantizer（可选）
}
```

### 分裂大聚类

```cpp
size_t IndexIVF::split_large_clusters(...) {
    // 1. 找出需要分裂的聚类
    // 2. 对每个聚类：
    //    - 获取所有向量
    //    - 使用k-means分裂
    //    - 保存新质心
    // 3. 创建新的ArrayInvertedLists（扩展nlist）
    // 4. 迁移现有数据（排除需要重新分配的向量）
    // 5. 添加新质心到quantizer
    // 6. 重新添加向量（自动分配到新聚类）
}
```

### 合并小聚类

```cpp
size_t IndexIVF::merge_small_clusters(...) {
    // 1. 找出需要合并的小聚类
    // 2. 对每个小聚类：
    //    - 找到最近的聚类（基于质心距离）
    //    - 获取小聚类的所有向量
    //    - 移除向量
    //    - 强制重新分配到最近的聚类
}
```

## 使用示例

```cpp
// 创建索引
faiss::IndexIVFFlat index(&quantizer, d, nlist);
index.set_direct_map_type(faiss::DirectMap::Hashtable);

// ... 添加、更新、删除操作 ...

// 动态维护聚类
size_t avg_size = index.ntotal / index.nlist;
size_t split_threshold = avg_size * 3;
size_t merge_threshold = avg_size / 3;

// 方式1：单独调用
index.recompute_centroids(true);
index.split_large_clusters(split_threshold, 2);
index.merge_small_clusters(merge_threshold);

// 方式2：综合维护（推荐）
auto stats = index.maintain_clusters(split_threshold, merge_threshold, 2, true);
printf("维护完成: 分裂了%zd个聚类，合并了%zd个聚类\n", 
       stats.clusters_split, stats.clusters_merged);
```

## 注意事项

1. **direct_map要求**：
   - `split_large_clusters` 和 `merge_small_clusters` 需要 `direct_map.type == Hashtable` 或 `NoMap`
   - `recompute_centroids` 不需要direct_map

2. **性能考虑**：
   - 分裂和合并操作会重建部分索引，可能较慢
   - 建议在批量操作后统一执行维护
   - 可以设置合理的阈值避免频繁维护

3. **nlist变化**：
   - 分裂操作会增加 `nlist`
   - 合并操作不会减少 `nlist`（只是清空列表）
   - 需要相应调整 `nprobe`

4. **数据一致性**：
   - 维护操作会临时移除和重新添加向量
   - 确保在维护期间不要进行其他操作
