# IndexIVF 自动聚类维护功能使用说明

## 概述

修改后的 `IndexIVF` 实现了**自动聚类维护**功能。在插入、更新或删除向量后，系统会自动维护被操作的聚类，确保索引质量。

## 核心特性

1. **自动维护**：插入/删除/更新操作后自动维护被影响的聚类
2. **局部维护**：只维护被操作的聚类，不对无关聚类进行多余操作
3. **智能策略**：
   - 聚类偏大（>平均大小×3）→ 分裂
   - 聚类偏小（<平均大小÷3）→ 合并
   - 聚类大小适中 → 重新计算质心
4. **量化器同步**：维护后自动更新 quantizer 中的质心，保持一致性

## 基本使用步骤

### 1. 创建索引并训练

```cpp
#include <faiss/IndexFlat.h>
#include <faiss/IndexIVFFlat.h>
#include <faiss/invlists/DirectMap.h>

int d = 64;           // 向量维度
int nlist = 100;      // 聚类数量

// 创建量化器
faiss::IndexFlatL2 quantizer(d);

// 创建 IVF 索引
faiss::IndexIVFFlat index(&quantizer, d, nlist);

// 训练索引（使用训练数据）
index.train(n_train, train_vectors);

// 设置 nprobe（搜索时探查的聚类数量）
index.nprobe = 10;  // 建议设置为 nlist 的 10% 左右
```

### 2. 启用 direct_map（必需）

**重要**：必须启用 `direct_map` 才能支持插入、更新、删除和自动维护。

```cpp
// 使用 Hashtable 类型以支持任意 ID
index.set_direct_map_type(faiss::DirectMap::Hashtable);
```

### 3. 添加数据

```cpp
// 准备数据
float* vectors = ...;  // 向量数据，size = n * d
idx_t* ids = ...;      // 向量 ID，size = n

// 添加数据（会自动维护被插入的聚类）
index.add_with_ids(n, vectors, ids);

// 注意：插入操作后已自动维护被插入的聚类
```

### 4. 更新数据

```cpp
// 准备要更新的数据
float* new_vectors = ...;  // 新的向量数据
idx_t* ids_to_update = ...;  // 要更新的向量 ID

// 更新向量（会自动维护被操作的聚类）
index.update_vectors(n_update, ids_to_update, new_vectors);

// 注意：更新操作（删除+插入）后已自动维护被操作的聚类
```

### 5. 删除数据

```cpp
#include <faiss/impl/IDSelector.h>

// 准备要删除的 ID
std::vector<idx_t> ids_to_delete = {100, 200, 300, ...};
faiss::IDSelectorArray selector(ids_to_delete.size(), ids_to_delete.data());

// 删除向量（会自动维护被删除向量所在的聚类）
size_t n_removed = index.remove_ids(selector);

// 注意：删除操作后已自动维护被删除向量所在的聚类
```

### 6. 搜索

```cpp
float* query_vectors = ...;  // 查询向量，size = nq * d
int k = 10;                  // 返回 top-k 结果

idx_t* labels = new idx_t[nq * k];
float* distances = new float[nq * k];

index.search(nq, query_vectors, k, distances, labels);

// 使用结果...
```

## 自动维护的工作原理

### 插入操作流程

```
1. 向量按原量化器分配到聚类
   ↓
2. 添加到对应的倒排列表
   ↓
3. 收集被插入的聚类
   ↓
4. 对每个被插入的聚类：
   - 检查聚类大小
   - 如果偏大 → 分裂成多个子聚类
   - 如果偏小 → 合并到最近的聚类
   - 如果适中 → 重新计算质心
   ↓
5. 更新 quantizer 中的质心
```

### 删除操作流程

```
1. 收集被删除向量所在的聚类（通过 direct_map）
   ↓
2. 从倒排列表中删除向量
   ↓
3. 对每个被删除向量所在的聚类：
   - 检查聚类大小
   - 如果偏小 → 合并到最近的聚类
   - 如果适中 → 重新计算质心
   ↓
4. 更新 quantizer 中的质心
```

### 更新操作流程

```
更新 = 删除 + 插入
   ↓
自动触发两次维护（删除后维护 + 插入后维护）
```

## 高级功能

### 手动维护特定聚类

如果需要手动维护特定聚类，可以使用：

```cpp
// 重新计算单个聚类的质心
bool updated = index.recompute_cluster_centroid(list_no, true);

// 维护单个聚类（检查大小并执行分裂/合并/重新计算）
faiss::IndexIVF::ClusterMaintenanceStats stats = 
    index.maintain_cluster(
        list_no,           // 聚类索引
        split_threshold,   // 分裂阈值（平均大小×3）
        merge_threshold,   // 合并阈值（平均大小÷3）
        2,                 // 分裂因子
        true               // 更新 quantizer
    );
```

### 全局维护（可选）

如果需要全局维护所有聚类：

```cpp
// 重新计算所有聚类的质心
size_t n_recomputed = index.recompute_centroids(true);

// 分裂所有大聚类
size_t n_split = index.split_large_clusters(split_threshold, 2, 100);

// 合并所有小聚类
size_t n_merged = index.merge_small_clusters(merge_threshold);

// 综合维护
faiss::IndexIVF::ClusterMaintenanceStats stats = 
    index.maintain_clusters(
        split_threshold,
        merge_threshold,
        2,
        true
    );
```

**注意**：通常不需要手动调用全局维护，因为插入/删除/更新操作已经自动维护了被影响的聚类。

## 注意事项

1. **必须启用 direct_map**：`set_direct_map_type(DirectMap::Hashtable)` 是必需的
2. **设置合适的 nprobe**：删除操作后某些列表可能变空，建议增加 nprobe
3. **ID 管理**：使用 `add_with_ids` 时，确保 ID 唯一且合理
4. **性能考虑**：自动维护会增加插入/删除/更新的时间，但能保持索引质量
5. **线程安全**：当前实现不是线程安全的，多线程环境下需要加锁

## 故障排除

1. **编译错误**：确保已正确编译 faiss 库，并设置了正确的包含路径和库路径
2. **运行时错误**：检查是否启用了 direct_map，以及 ID 是否有效
3. **性能问题**：如果自动维护耗时过长，可以考虑批量操作后手动调用全局维护
